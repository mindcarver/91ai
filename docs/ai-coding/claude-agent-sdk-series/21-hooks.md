# Hooks：把你的代码织进 agent 的生命周期

> 更新日期：2026/10

**TL;DR：** Hook 是 SDK 里最强的控制点：在工具调用前后、提示提交时、任务停止时、子代理起止时、压缩前后等事件点上，你的回调被同步调用，可以放行、拒绝、改写参数、改写输出、追加上下文。它们排在权限评估链的最前面，拒绝全局生效。多钩子并行执行取最严决定，超时各有语义。文件态钩子和代码态钩子并存。这篇按事件地图、决定语义、超时行为、实战模式四块讲透。

## Hook 在整个体系里的位置

前面几篇已经多次撞见钩子：权限篇说它排在评估链第一道门、拒绝全局优先；介入篇说全量审计靠它；上下文篇说压缩前有钩子。现在正面讲它。

钩子的本质是一个同步介入点协议：引擎在生命周期的固定事件上暂停，把事件数据递给你的函数，等你的函数返回一个决定，再按决定继续。这个协议的三个特性决定了它的地位：时机在一切之前（权限判定前）、能力是完整的（改参数改输出改上下文）、语义是同步的（引擎真的在等你）。

与审批回调的分工一句话分清：回调裁决"这个调用可以吗"（权限语义），钩子介入"这个事件发生时我要做什么"（策略与观测语义）。两者的能力有重叠（都能拒绝工具调用），但钩子看得见所有事件（回调只见需要批准的），回调专精人机裁决。

## 事件地图

两门语言共有的事件构成本体。工具生命周期三件：调用前、调用后（成功）、调用后（失败）。会话节奏四件：用户提示提交时、任务停止时、子代理启动与停止时、压缩前。还有权限等待时（引擎在等人的批准，用它发通知）和通知事件。

TS 侧额外多出一大批，覆盖更细的生命周期：会话开始与结束、模型切换前后、批量工具执行后、消息展示时、压缩后、目录与文件变化等。Python 侧有一个已知缺口：会话开始与结束两个事件在类型层没有暴露，不能注册为代码回调，只能以 shell 命令形式放在设置文件里。这个不对称是跨语言移植钩子代码时的头号检查点。

事件按用途分三组记忆。控制组：调用前、提示提交（这两个能改行为）。观测组：调用后、子代理起止、会话起止（记录与审计）。节奏组：停止、压缩前、权限等待（挂载流程逻辑）。

## 匹配器：订阅的过滤器

注册钩子时配匹配器限定订阅范围。工具类事件按工具名匹配：精确名、竖线分隔的名单、正则皆可，不传匹配器等于全订阅。注意匹配的对象只有工具名，不匹配参数和路径：想"只在写 .env 文件时触发"，匹配器写写入和编辑两个工具名，路径判断在回调内部自己做（事件数据里有完整参数）。这个两段式（匹配器粗筛、回调细判）是标准写法。

MCP 工具的名字带命名空间，匹配器里可以按服务器前缀用正则圈一整台服务器。

## 决定语义：回调能返回什么

不同事件的返回能力不同，按事件分。

调用前是能力最强的：可以给权限决定（放行、拒绝、转问、延迟四选）、可以附理由、可以改写工具参数。改参数配放行就是"消毒后自动批准"，配转问就是"改完让人确认"，不带决定只改参数则流入正常权限流程（仅消毒不放权）。延迟是个特殊决定：本轮以工具被延迟收尾，会话可稍后恢复继续，适合"这个操作要等外部流程"的场景。

调用后的返回面向结果：可以给工具结果追加内容（模型看到你的补充说明）、可以整体替换输出（过滤敏感信息后替换）、TS 还能给自动模式的分类器附注说明。

提示提交时能往用户提示后面附加上下文，这是运行时动态注入指令的正规通道（系统提示篇讲过中途改提示不生效，这里是答案）。

非工具事件的返回多为流程性的：停止事件的返回可以阻止或影响结束行为。

两个通用字段：面向人的系统消息（给界面展示，不给模型）和继续标记。还有异步模式：声明异步执行的钩子只做旁观（副作用），不能阻塞也不能修改，引擎不等你。

## 多钩子与超时

同一事件可挂多个钩子，全部并行执行，权限决定取最严（拒绝压过延迟压过转问）。设计推论：钩子之间要相互独立，谁先完成不确定，别在钩子间设计顺序依赖。

超时按事件有默认档位，大部分事件十分钟，提示提交类三十秒，会话结束预算一点五秒。超时的后果分事件：调用前超时跳过这次工具执行（模型收到超时结果），提示提交超时阻止该提示，停止类超时视为无决定，会话结束超时直接放弃剩余工作。超时值可按钩子配置，慢速外部调用（人工审批系统、慢数据库）要显式放宽。

钩子里的异常处理责任在你：接住、记录、按"无决定"返回。抛出去的异常不是 deny 也不是 allow，行为依赖引擎的容错路径，别拿异常当控制流。

## 文件态与代码态的并存

设置文件里的钩子（shell 命令、HTTP 调用等）和代码里注册的回调并存于同一会话，同一事件上两类都会触发。这带来一个迁移路径：团队既有 CLI 的文件钩子先原样生效，SDK 程序逐步把关键逻辑改写为代码回调（类型安全、可测试），最后按需清理文件侧。反过来也要意识到：清空配置来源后文件钩子消失，但代码钩子还在，会话的行为不会完全归零。

## 四个实战模式

模式一，高危路径防护：调用前钩子匹配写入和编辑，回调里查参数里的文件路径，命中敏感清单就拒绝并给模型一句替代建议。这是权限规则的动态版：清单可以来自数据库实时更新，规则文件做不到。

模式二，写重定向：调用前钩子把参数里的目标路径改写到沙箱目录再放行。agent 以为在改源码，实际改的是隔离副本，评审后合并。消毒能力的典型应用。

模式三，审计流水：调用后钩子把每次工具调用记入审计系统（工具名、参数摘要、结果状态、关联的任务标识）。权限篇说过回调看不见被放行的调用，钩子看得见全部，审计必须用钩子。

模式四，进度外联：权限等待钩子把"agent 在等批准"推到 Slack，通知事件转发系统提示。无人值守系统的眼睛。

四个模式共同说明钩子的定位：**凡是"每次都要"的逻辑放钩子（审计、防护、消毒），凡是"偶尔要人"的逻辑放回调（裁决）**。

## 权衡与局限

钩子在你的关键路径上：每个工具调用前都要过你的代码，钩子的延迟直接加进 agent 的每一步。慢钩子是全局税。对策：控制组钩子保持极简（纯内存判断），观测组钩子声明异步（不阻塞），慢外部系统全部推到事件侧而非调用前侧。

钩子代码的质量要求也高于普通代码：一个抛异常的钩子能在每次工具调用上制造噪音，一个死循环的钩子能挂死整个会话。测试覆盖、超时兜底、独立部署节奏，把钩子当基础设施代码对待。

最后是调试复杂度：行为 = 引擎逻辑加你的钩子矩阵，出问题时先分辨哪一层。技巧是把钩子的每次触发记一行结构化日志（事件、匹配器、决定、耗时），排障时日志就是钩子层的飞行记录仪。

## 一个钩子的完整开发过程

以最高频的防护钩子为例走完整过程：目标是阻止 agent 写入任何点 env 结尾的文件，同时给模型一句有用的替代建议。

第一步定事件与匹配器。写文件的动作来自写入和编辑两个工具，事件选调用前，匹配器写这两个工具名的名单。匹配器只到工具名这一层，文件路径的判断留给回调。

第二步写回调骨架。入参里取工具名和输入数据（输入里的文件路径字段是判断依据），处理逻辑三行：路径为空直接放行（不是文件操作）；路径命中模式返回拒绝加理由；其余放行。返回形状按调用前的规范：权限决定加理由字段，理由写给模型看（"环境变量文件受保护，如需修改配置请使用配置工具"）。

第三步把钩子挂进会话并验证。挂载就是选项里注册，验证做三轮：正向（让它改普通代码文件，钩子放行，行为与无钩子一致）；负向（让它改 env 文件，钩子拒绝，模型收到理由且尝试了替代路径）；边界（路径大小写变体、相对路径绝对路径、符号链接）。边界轮最重要，路径匹配的经典漏洞全在这一轮暴露。

第四步补工程质量。超时给个两秒（纯内存判断用不了默认十分钟）；异常自己接住按放行返回并记日志（钩子挂掉不能挡业务，除非你的安全策略要求 fail-closed，那就按拒绝返回，两种选择都合法，选哪个写进注释）；触发日志一行结构化输出（时间、路径、决定）。

第五步回归。钩子的每次改动跑那三轮验证，三轮脚本化进 CI。钩子是"改一行就敢上生产的代码"的反面，它的失效模式是静默的（防护突然消失或突然拦截一切），自动回归是唯一的保险。

整个过程两小时，产出的钩子十行左右。钩子开发的真实成本不在写代码，而在验证矩阵的维护。

## 钩子机制的五个疑问

**钩子和权限规则都拦同一个东西，用哪个？** 静态可枚举的用规则（路径清单、命令模式），需要运行时信息的用钩子（清单来自数据库、要查调用上下文）。规则是声明式的好审计，钩子是命令式的好灵活，先规则后钩子。

**钩子能阻止子代理吗？** 能，钩子在子代理里同样触发（继承篇讲过）。这是全局防护的正确落点：主会话的规则不一定约束子代理，钩子跟着每个代理进程走。

**一个事件挂了三个钩子，执行顺序？** 并行执行无顺序，权限决定取最严。所以钩子间不能有依赖，需要顺序的逻辑合成一个钩子写。

**钩子超时的默认十分钟太长，短任务等不起？** 按钩子配置超时，控制类钩子给秒级。另注意调用前超时的语义是跳过执行（偏保守），如果你的钩子只是记日志，超时跳过等于这次调用被拒了模型会绕路，纯观测钩子声明异步更合适。

**能动态开关钩子吗？** 钩子注册在会话启动时，中途增删做不到。动态策略的做法：钩子常驻，行为开关在回调内部读配置中心，钩子变薄、策略变数据。

## 钩子矩阵：事件与用途的对位

把常用事件和典型用途摆成矩阵，设计钩子体系时按格取用。

| 事件 | 观测用途 | 控制用途 | 慎用提示 |
| --- | --- | --- | --- |
| 调用前 | 调用审计全量流水 | 拒绝高危、改参消毒、写重定向 | 在关键路径上，保持毫秒级 |
| 调用后 | 结果体积与成功率统计 | 追加上下文、替换输出 | 异步声明可避开阻塞 |
| 提示提交 | 输入审计 | 动态注入指令上下文 | 注入内容会进上下文，控制体积 |
| 子代理起止 | 委派审计、归因打标 | 记录委派树 | 无 |
| 压缩前 | 压缩事件审计 | 状态快照归档 | 无 |
| 停止 | 任务完成审计 | 阻止过早收尾 | 返回影响会话结束，语义要查文档用对版本 |
| 权限等待 | 等待时长统计 | 外联通知（Slack、推送） | 只通知不决策，决策在回调 |
| 会话起止（TS） | 会话生命周期审计 | 资源准备与清理 | 结束钩子预算一点五秒，极简 |

矩阵的三条读法。控制列从上到下权力递减：调用前全能，会话起止只剩旁路。观测列全部可声明异步（不阻塞），控制列必须同步（要等你的决定）。慎用列是延迟账：每一行都标了它的性能代价，钩子体系的设计就是把最重的逻辑挪到最便宜的行。

一个成熟系统的钩子布局通常是：调用前一枚（安全总闸）、调用后一枚异步（审计）、权限等待一枚（通知）、会话起止一对（TS，资源管理）。四枚钩子覆盖九成需求，先这四枚起步，矩阵里其他格子等真需求来了再填。

起步顺序也有讲究：先挂调用后异步的审计钩子（零风险，先攒数据），再上权限等待的通知，最后才上调用前的控制钩子（它一出问题就挡业务）。每加一枚钩子，先让它的触发日志空跑一天再接真实逻辑，矩阵里每一格的延迟账，都用实测数字去填。

补一条跨语言的工程备忘：同一套钩子逻辑要在两种 SDK 里维护时，把业务判断抽成共享的核心（纯函数：事件数据进、决定出），两个语言的钩子都做薄壳。钩子的移植坑（类型不对称、事件面差异）被壳隔离，核心逻辑一份测试两处复用。这是钩子代码从"能用"到"可维护"的分水岭。

## 关键要点

- 钩子是最强控制点：时机在权限链之前，能改参数改输出追加上下文；回调管人机裁决，钩子管全量策略与观测。
- 事件三组：控制（调用前、提示提交）、观测（调用后、子代理起止）、节奏（停止、压缩前、权限等待）；Python 缺会话起止的代码回调。
- 匹配器只匹配工具名，参数路径判断在回调内做；多钩子并行取最严，超时语义分事件。
- 异步钩子只旁观不阻塞；钩子异常自己接，别当控制流。
- 四模式：高危防护、写重定向、审计流水、进度外联；"每次都要"用钩子，"偶尔要人"用回调。
